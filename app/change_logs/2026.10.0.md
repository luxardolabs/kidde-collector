Two guard catch-ups (luxarch 0.141.0 → 0.249.0, luxlint 0.44.2 → 0.60.1, luxaudit 0.4.0 → 0.12.0) that ended in a security release: the shipped `2026.09.0` image carried 27 fixable HIGH/CRITICAL vulnerabilities that the lockfile scan could never see, and this image carries none. Also: one `compose.yml` with profiles in place of five compose files, and a commit-identity scrub of the pre-transfer history.

## Refactors

- **One `compose.yml`, five profiles** (`repo.compose_conventions`), replacing `compose.{demo,dev,e2e,prod}.yml`. The collector carries no profile and runs in every stack; influx, grafana and the fake carry theirs. Environments are `.env.<env>`: a new committed `.env.e2e`, an extended `.env.demo`, and compose wiring in `.env.example`. Profile resolution was verified per stack, not assumed.
- **Local-only images are BARE** (`repo.image_name_declares_provenance`): `kidde-collector:local` and `kidde-collector-fake:local`, previously `ghcr.io/luxardolabs/…:local`. A registry-qualified name promised an artifact that was never pushed, so a `docker image prune` would have left the stack nothing to pull. Compose resolves an **empty `REGISTRY`** to the bare name: `${REGISTRY:+${REGISTRY}/luxardolabs/}kidde-collector:${TAG}`.
- **Re-emitted fleet assets**: the Claude-Code hook set, the CLAUDE.md conduct pointer (v4), both writing guides, the `guard-upgrade` marker, and the `gitleaks` asset v8. The canonical recipe replaced the hand-written one.
- **`make status`** writes each guard's JSON to a per-run `mktemp` (it was a fixed `/tmp/lux.json` shared by every repo on the host). It refuses to stamp another guard's output, and passes `LUXARCH_STATUS_WRITE=1` so luxarch does not judge the files it is replacing.
- **`buildx-setup` refuses a stray per-project builder** beside the shared `luxardo-builder` (`repo.buildx_strays_refused`), with an `ALLOW_STRAY_BUILDERS=1` escape.
- Guard pins use `:=`, so an untracked `Makefile.local` cannot shadow them.

## Infra / Ops

**PRE-DEPLOY:** only if you run a **local build** (`TAG=local`) from your own `.env.dev`: set `REGISTRY=` (empty). With `REGISTRY=ghcr.io` and `TAG=local`, compose now looks for `ghcr.io/luxardolabs/kidde-collector:local`, which `make build-local` no longer produces. Registry deployments (`REGISTRY` set, `TAG=<version>`) are unaffected.

- **Shipped-image CVEs: 27 → 0 fixable HIGH/CRITICAL.** luxaudit 0.11.0 added an image leg that scans the released image itself, and `2026.09.0` failed it with 20 OS findings (openssl, perl-base, …) and 7 package findings, while the lockfile leg read 0 vulnerable. The runtime stage copied the builder's whole site-packages, so poetry, virtualenv, dulwich and pip's vendored urllib3/msgpack/setuptools shipped inside a collector that never runs them. Fixes:

  - poetry installs into its own `/opt/poetry` venv, so it never enters the copied site-packages;
  - the runtime stage runs `apt-get upgrade`;
  - pip is uninstalled from the runtime stage;
  - urllib3 2.7.0 → 2.8.0 in the lock (CVE-2026-97687/97689), the only lock change.

  The locally rebuilt image was measured at 0 with the Trivy baked into luxaudit before tagging.

- **Commit-identity scrub.** The gitleaks asset now also checks commit author/committer metadata, which a content scanner cannot see. 22 pre-transfer commits carried a personal author address. They live only on the `v2024.10.00` line, which shares no history with `main`. `git filter-repo --mailmap` rewrote their author, with trees, subjects and dates byte-identical to a mirror backup. `main` was untouched and pushed as a fast-forward. The `v2024.10.00` tag was force-pushed with a lease on its exact old SHA (`732b418` → `278fbb0`), and its GitHub Release stayed attached. `.gitleaksignore` fingerprints are keyed by commit SHA, so they were remapped through filter-repo's commit-map; otherwise 31 grandfathered content findings would have resurfaced.

- The gitleaks scanner is now the **pinned mirror** (`gitleaks:v8.30.1` beside the guards), replacing `ghcr.io/gitleaks/gitleaks:latest`. Its config is written to a per-run temp file instead of a shared `/tmp/gl.toml`, which at one point during this window held another repo's config.

- The `pre-push` hook also runs `guard-version-check`, advisory only. It caught two upstream releases mid-window (luxarch 0.248.0/0.249.0, luxlint 0.60.1), and both were bumped before tagging.

## Fixes

- `.env.example` told a local-build user `TAG=local` while leaving `REGISTRY=ghcr.io`, a pair that no longer resolves. It now says to leave `REGISTRY` empty for a local build.
