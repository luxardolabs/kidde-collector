## Features

- **Safety & Power dashboard row** (both dashboards). Ten fields were being written to InfluxDB and displayed nowhere — `co_alarm`, `co_level`, `peak_co_level`, `smoke_alarm`, `too_much_smoke`, `low_battery_alarm`, `end_of_life_alarm`, `battery_level`, `battery_state`, `lost`. Adds a per-device status table plus CO / Peak CO / Battery Level timeseries. Booleans aggregate with `last()`, not `mean()` (InfluxDB cannot aggregate a boolean); they render as OK/ALARM, OK/LOW, OK/REPLACE, OK/LOST on a colour background. CO carries a dashed threshold at 35 ppm. Verified against 8 live devices.
- **Coverage ratchet** wired into `make test` (`luxlint --coverage-ratchet`, floor in `.luxlint.toml [test].coverage_min`). Grew out of KIDDECOLLE-50: luxlint 0.44.0 shipped `--coverage-ratchet` citing that issue, because a floor could not live in a repo-local pytest config (`test.no_local_pytest_config` forbids one).
- `make mypy`, `make plan`, `make status`, `make guard-upgrade`, `make honest` targets.
- **Release documentation** (luxarch 0.137.0 `repo.release_docs_present` / `repo.release_docs_current`). This repo had none. Adds the per-version pair — this document and `app/release_notes/{VERSION}.md` — the two canonical writing guides emitted from the image, and root `CHANGELOG.md` / `RELEASE_NOTES.md` pointer files. Written per `--doc FLEET-RELEASE-PROCESS`, including the tracker reconciliation that found KIDDECOLLE-14.

## Refactors

- **Build backend → hatchling** with PEP 621 `[project]`; Poetry drops to `package-mode = false` and stays the dependency manager (lockfile untouched; both Dockerfiles still `poetry install --no-root`, so the backend is never exercised at image build). Removes the second version literal that could drift from `VERSION`.
- `VERSION` is the single source (`dynamic = ["version"]` + `[tool.hatch.version]`).
- **Canonical `make check` gate**: `guard-version-check honest lint mypy test arch audit gitleaks`. It previously dropped `mypy` (folded into `lint`) and had no `honest` step, so a rule family that scanned zero files could read green. `guard-version-check` is now FATAL rather than warn-only.
- `lint` and `mypy` are separate mount-only legs; the hand-rolled in-repo mypy tail and the hand-rolled `ruff format` are gone (`luxlint --format` is the canonical fixer). ruff, mypy and `types-aiofiles` left the dev group — no make target invoked them.
- Test suite: 40 → 160 tests across 8 files; coverage 41% → 99%. `client.py`, `endpoints.py`, `poller.py`, `logging.py`, `config.py`, `session.py` at 100%; `influxdb.py` and `health/check.py` at 98%; `main.py` at 91%.

## Infra / Ops

**PRE-DEPLOY:** none. Nothing an operator must do before upgrading.

- **InfluxDB is no longer published to the host** in dev/demo. The collector and Grafana both reach it over the compose network (`http://kidde_influxdb:8086`), so the publish served nothing inside the stack while colliding with any other InfluxDB on the machine. A commented `ports:` line is left in place for anyone who wants to poke the API by hand. Grafana still publishes on its default 3000 — that is unchanged and deliberately so.
- aiohttp **3.14.1 → 3.14.3**, clearing CVE-2026-69244 (out-of-bounds heap read in the C response parser while building the error message for a malformed response — we are a client, so a misbehaving Kidde endpoint or InfluxDB reaches it), CVE-2026-69243 (WebSocket-upgrade request smuggling) and CVE-2026-59881 (RSV1 frames decompressed without `permessage-deflate`). Declared as a floor in our own manifest, not just re-locked: influxdb-client pulls aiohttp through an unbounded range, so a plain re-lock resolves straight back to the vulnerable build.
- `VERSION` corrected to CalVer (`2026.8.0` → `2026.09.0`, zero-padded month).
- Release builds use the one shared, GC-capped fleet buildx builder (`luxardo-builder`, 20 GiB `keepBytes`) instead of a per-project `kidde-builder`, which held a separate cache with no dedup. Multi-arch amd64 + arm64 build validated without publishing.
- `make test` runs with `--network none`. Two tests were found silently calling the **real Kidde cloud** — `KiddeAPIEndpoints.LOGIN` is baked from `config.API_BASE_URL` at import, so a local test server was started but never targeted, and the 401/403 test passed because production answered 401. Now structurally impossible.
- Committed guard-status files (`.lux*-status.json`) via `make status`, so the fleet reads this repo's state instead of re-running every guard.
- Guard pins closed the window at luxarch **0.141.0** (from 0.137.0 at the time these documents were first written). 0.138.0 (canonical `NAMING_CONVENTION` + the collision-prone `column_0_name` trap) is alembic-gated and vacuous here; 0.139.0 fixes fastapi-web/n-plus-one false positives; 0.140.0 documents guard-maintainer escalation routing; 0.141.0 adds `repo.compose_command_no_orphan_flags` and settles headless release-notes badges. luxlint closed at 0.44.2, which prescribes `COVERAGE_CORE=sysmon` for the coverage ratchet (the default C tracer under-records async lines on Python 3.13 and would ratchet in a too-low floor); this repo is on 3.14, where the cores agree — the measurement is unchanged at 99%.
- `repo.compose_command_no_orphan_flags` (0.141.0) **passes**: a compose `command:` written as a YAML folded scalar orphans its flags onto a separate shell command — silently, since the container still starts and passes its healthcheck (it shipped a proxy-trust hole in another repo). Every compose command here is exec-form, which the rule skips as immune.
- Fleet secret hooks re-emitted (the committed pre-commit hook lacked the commit-identity guard). It blocked two commits during this window, correctly both times: a token-shaped test fixture, and an internal node name on the org denylist. Both fixed at the fixture, never by allowlisting the scanner.

## Fixes

- **Root-logger hijack** (`app/core/config.py`, 5 sites) — `logging.warning()` implicitly configures the root handler on first use for every importer, bypassing the collector's own handler from `app/utils/logging.py`. Now a module logger.
- **Healthcheck could report a stalled collector as healthy** (`app/health/check.py`) — the capture-age comparison used naive local wall-clock, which is not monotonic across a DST fall-back: a capture written 01:30 CDT and read 01:30 CST (a real hour later) subtracts to 0 s. Fails open, one hour, twice a year, on non-UTC containers. Both operands are now absolute UTC. (An earlier commit message in this window overstated this as an always-on bug on any non-UTC host; `fromtimestamp()` without a tz also converts to local, so the two sides were consistently local. The DST fold is the real defect.)
- **Blocking filesystem calls on the event loop** (`app/collector/session.py`) — `.exists()` and `.chmod()` moved off with `asyncio.to_thread`.
- **InfluxDB teardown errors were silently discarded** (`app/storage/influxdb.py`) — a broad `contextlib.suppress(Exception)` around client close. Now caught and logged at warning; deliberately not re-raised, since re-raising in a close path replaces the real shutdown cause with a socket error.
- `_age_seconds` narrowed from a bare `except Exception` to the parse failures that can actually occur — an unparseable timestamp is a data condition, not an error.
