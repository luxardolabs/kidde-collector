# 2026.10.2 — 2026-10-10

Fixes from the adversarial pass on 2026.10.1. Startup logs are JSON-only, URL credentials are never logged, and a bad InfluxDB URL says why the collector exits. The release recipe gains the gates the pass showed were missing.

## Issues Closed

- KIDDECOLLE-60 — Adversarial pass on 2026.10.1: 7 confirmed breaks (6 in the release path, 1 in the logging contract) and 0 secret leaks, all fixed. Also fixed: 3 pre-existing problems in the touched files.

None.

## Refactors

- `config._warn` / `config.flush_warnings()`: config is read at import, before `configure_logging()`. A warning raised then is now held and logged after the fleet handler is installed (`app.main` calls `flush_warnings()` right after `configure_logging()`). Held warnings are stored pre-formatted, so the log call names its one field (`repo.log_fields_explicit`).
- `config.redact_url()` replaces `user:password@` in a URL with `***@`. It's used by `describe_settings` and by InfluxDB's connect-failure and health-check records.

## Infra / Ops

- **Release recipe gates** (Makefile; no effect on a running collector):
  - `release`, `version-build-push` and `release-public` run `make audit` first. The image scan only refuses fixable HIGH/CRITICAL, so a MEDIUM CVE in a locked package (multidict CVE-2026-104874) passed it.

  - Before any push, `release_preflight` checks:

    - `v$(VERSION)` is at HEAD locally AND on origin;
    - the release notes exist;
    - `gh` is installed and authenticated.

    A push followed by a failing `gh-release` used to burn the version.

  - `version-build-push` takes the same gated multi-arch candidate path (no `:latest`, no Release). It had pushed `:VERSION` single-arch from an untagged HEAD, which would block the multi-arch release for good.

  - The clean-tree gate also refuses gitignored files under `app/`. `.dockerignore` uses `**/` patterns for caches and `output/`: a bare pattern matches only at the context root, so `app/output/cookies.json` (a live session cookie) could ship.

  - The scan reads the candidate's digest before and after scanning and refuses if it moved. It then removes the host's local copy of the scanned tag, which `pull --platform` had re-pointed at arm64.

## Fixes

- **Config warnings were plain text on stderr.** These are the warnings raised at import: a cleartext `http://` URL to a remote host, or an out-of-range or invalid value. They went to `logging.lastResort` and bypassed the JSON stream. `.env.example`'s own URL triggers the cleartext warning on every start.
- **A URL with credentials was logged in full** in the startup settings and the InfluxDB connect-failure record. The cleartext warning read the host by string slicing, so `http://user:pass@host` logged `user` as the host. The host is now read with `urlsplit`.
- **A malformed InfluxDB URL exited 1 with no log record.** It now logs `Startup aborted: Invalid InfluxDB URL format: …`.
- **An unset setting showed as `****`**, which reads as configured. It now shows `<unset>`.
